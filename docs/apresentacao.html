database.py

Conexão com o MySQL

# 1) Configurações lidas do .env automaticamente
class Settings(BaseSettings):
    DATABASE_URL: str     # ex: mysql+pymysql://root:senha@localhost:3306/concessionaria
    SECRET_KEY: str       # chave para assinar JWT
    ALGORITHM: str = "HS256"
    ACCESS_TOKEN_EXPIRE_MINUTES: int = 480  # 8 horas

# 2) Engine: gerencia o pool de conexões com o MySQL
#    pool_pre_ping=True → testa a conexão antes de usar (evita "server has gone away")
engine = create_engine(settings.DATABASE_URL, pool_pre_ping=True)

# 3) Fábrica de sessões: cada requisição ganha a sua
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)

# 4) Base declarativa: todos os models herdam dela
Base = declarative_base()

# 5) Dependência do FastAPI: abre sessão → entrega → fecha ao terminar
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

🧩

O que é ORM?

Object-Relational Mapping: cada classe Python vira uma tabela no MySQL. Você escreve db.query(Veiculo).all() e o SQLAlchemy traduz para SELECT * FROM veiculos.

🔒

Segurança automática

ORM previne SQL injection — você nunca concatena strings no SQL.

🔗

Foreign Keys

Uma Transacao aponta para Cliente, Veiculo e Funcionario via ForeignKey — o banco garante a integridade.

04

Segurança: JWT + bcrypt

Autenticação robusta e autorização em cascata.

auth.py

Hash de senhas

# bcrypt: hash lento, com salt aleatório por senha
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

def hash_senha(senha: str) -> str:
    return pwd_context.hash(senha)

def verificar_senha(senha: str, hash_: str) -> bool:
    return pwd_context.verify(senha, hash_)
🔐

Por que bcrypt?

É um algoritmo lento de propósito. Um ataque de força bruta que testaria milhões de senhas por segundo com MD5 cai para centenas por segundo com bcrypt.

🧂

Salt automático

Dois usuários com a mesma senha geram hashes diferentes. Impossível usar rainbow tables.

🚫

Nunca em texto puro

A senha real só existe na memória durante o POST /auth/login. Depois disso, só o hash circula.

auth.py

Tokens JWT

def criar_token(data: dict) -> str:
    payload = data.copy()
    payload["exp"] = datetime.utcnow() + timedelta(minutes=480)
    return jwt.encode(payload, SECRET_KEY, algorithm="HS256")

def get_current_user(token: str = Depends(oauth2_scheme),
                     db = Depends(get_db)):
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=["HS256"])
        cpf = payload.get("sub")
    except JWTError:
        raise HTTPException(401, "Credenciais inválidas")
    user = db.query(Funcionario).filter(Funcionario.cpf == cpf).first()
    if not user: raise HTTPException(401)
    return user

🛡️

Assinatura = prova

Se alguém alterar o payload (ex: mudar cargo para "adm"), a assinatura deixa de bater e o token é rejeitado.

dependencies.py

Autorização por cargo

# Fluxo em cascata: cada nível chama o anterior
def require_adm(user: Funcionario = Depends(get_current_user)):
    if user.cargo != CargoEnum.ADM:
        raise HTTPException(403, "Acesso restrito a ADM")
    return user

def require_vendedor(user = Depends(get_current_user)):
    if user.cargo not in (CargoEnum.VENDEDOR, CargoEnum.ADM):
        raise HTTPException(403, "Acesso restrito a Vendedor")
    return user

def require_oficina(user = Depends(get_current_user)):
    if user.cargo not in (CargoEnum.OFICINA, CargoEnum.ADM):
        raise HTTPException(403, "Acesso restrito à Oficina")
    return user
🔽

Cascata

require_adm → get_current_user → valida JWT → busca no banco. Se qualquer passo falha, a requisição nem chega na rota.

♻️

Reutilizável

Basta adicionar _=Depends(require_adm) no endpoint e a proteção é aplicada.

🚫

403 vs 401

401 = não autenticado (token inválido).
403 = autenticado, mas sem permissão.

Banco

Chaves primárias e escolhas

PK

CPF como chave

Funcionários e clientes usam o CPF como PK. Motivo: é o identificador natural do domínio — único, estável, conhecido por todos.

PK

Chassi como chave

Veículos usam chassi (17 caracteres). É único por lei em todo o mundo, impossível duplicar.

PK

ID auto para logs

Transações e ordens de serviço usam ID auto-increment. Elas são eventos e podem ter múltiplos por dia.

🔗

Foreign Keys

Cada FK cria um vínculo garantido pelo banco. Se tentar criar uma transação com cliente_cpf inexistente, o MySQL rejeita automaticamente. Isso protege a integridade mesmo se o backend falhar.

Regra de negócio

Como funciona uma venda

@router.post("/venda", response_model=TransacaoOut, status_code=201)
def venda(dados: TransacaoCreate,
          db: Session = Depends(get_db),
          user: Funcionario = Depends(require_vendedor)):

    # 1) Cliente precisa existir
    if not db.query(Cliente).filter(Cliente.cpf == dados.cliente_cpf).first():
        raise HTTPException(404, "Cliente não encontrado")

    # 2) Veículo precisa existir
    v = db.query(Veiculo).filter(Veiculo.chassi == dados.veiculo_chassi).first()
    if not v: raise HTTPException(404, "Veículo não encontrado")

    # 3) Regra: não pode estar vendido
    if v.situacao == SituacaoVeiculo.VENDIDO:
        raise HTTPException(400, "Veículo já vendido")

    # 4) Cria a transação (vendedor vem do JWT, não do frontend!)
    t = Transacao(tipo=TipoTransacao.VENDA,
                  valor=dados.valor or v.preco,
                  cliente_cpf=dados.cliente_cpf,
                  veiculo_chassi=dados.veiculo_chassi,
                  vendedor_cpf=user.cpf)  # ← segurança

    # 5) Baixa automática no estoque
    v.situacao = SituacaoVeiculo.VENDIDO

    # 6) Atômico: ou tudo, ou nada
    db.add(t); db.commit(); db.refresh(t)
    return t

Responsável por criar a engine, gerenciar o pool de conexões e fornecer sessões às rotas.

# 1. Settings — lê as variáveis do arquivo .env automaticamente
class Settings(BaseSettings):
    DATABASE_URL: str
    SECRET_KEY: str
    ALGORITHM: str = "HS256"
    ACCESS_TOKEN_EXPIRE_MINUTES: int = 480

    class Config:
        env_file = ".env"

settings = Settings()

# 2. Engine — fábrica de conexões com pool automático
engine = create_engine(settings.DATABASE_URL, pool_pre_ping=True)

# 3. SessionLocal — fábrica de sessões (1 por requisição)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)

# 4. Base — classe mãe de todos os models
Base = declarative_base()

# 5. Dependência do FastAPI
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
🔌

Engine

É o "motor" que fala com o MySQL. Faz o pool de conexões (reaproveita em vez de abrir/fechar a cada request). pool_pre_ping=True testa a conexão antes de usar.

📦

SessionLocal

Fábrica de sessões. Cada requisição HTTP ganha a sua própria sessão — isolamento garantido.

🧬

Base

Classe mãe. Toda tabela em models.py herda dela, para o SQLAlchemy saber o que precisa criar no banco.

♻️

get_db() — yield

O yield entrega a sessão à rota e garante que ela seja fechada no finally, mesmo se a rota der erro.

class Funcionario(Base):
    __tablename__ = "funcionarios"
    cpf = Column(String(11), primary_key=True, index=True)
    nome = Column(String(80), nullable=False)
    email = Column(String(120), unique=True, nullable=False)
    senha_hash = Column(String(255), nullable=False)
    cargo = Column(Enum(CargoEnum), nullable=False)
    data_cadastro = Column(DateTime, server_default=func.now())
🔑

Chave primária = CPF / Chassi

Usamos identificadores naturais do domínio em vez de criar um id artificial. CPF é único por lei; chassi também.

🔗

ForeignKey

Column(String(11), ForeignKey("funcionarios.cpf")) cria uma relação garantida pelo MySQL. Não deixa inserir referência inexistente.

🎯

Enums no banco

Enum(CargoEnum) vira ENUM('adm','vendedor','oficina'). O MySQL rejeita qualquer valor fora disso — segurança de dados em nível de schema.

Arquivo · schemas.py

Contratos de dados (Pydantic)

Define o formato JSON aceito e devolvido por cada endpoint. Validação automática.

# 1. BASE — campos comuns a Create e Out
class VeiculoBase(BaseModel):
    chassi: str = Field(..., min_length=17, max_length=17)
    marca: str
    modelo: str
    ano: int
    categoria: CategoriaVeiculo
    preco: Decimal
    placa: Optional[str] = None
    quilometragem: int = 0

# 2. CREATE — payload do POST
class VeiculoCreate(VeiculoBase):
    pass

# 3. UPDATE — payload do PUT (todos opcionais)
class VeiculoUpdate(BaseModel):
    marca: Optional[str] = None
    modelo: Optional[str] = None
    situacao: Optional[SituacaoVeiculo] = None

# 4. OUT — resposta da API
class VeiculoOut(VeiculoBase):
    situacao: SituacaoVeiculo
    class Config: from_attributes = True
📋

Por que 4 versões?

  • Base — campos comuns (evita repetição)
  • Create — o que o cliente manda no POST
  • Update — tudo opcional (atualiza só o que veio)
  • Out — o que a API devolve (com campos gerados)
✅

Validação grátis

Se o cliente mandar chassi com 10 caracteres, o FastAPI devolve HTTP 422 antes da rota executar. Nada de validação manual com if/else.

📖

Swagger automático

Os schemas alimentam /docs. A documentação da API é gerada automaticamente, mostrando exemplo de payload e resposta.

🔒

Nunca expor hash

FuncionarioOut não tem campo senha_hash. A senha nunca sai do servidor, nem em resposta.

Arquivo · auth.py

Autenticação e JWT

Hash de senhas, criação de tokens e extração do usuário autenticado.

# 1. Contexto bcrypt (hash de senha)
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

def hash_senha(s): return pwd_context.hash(s)
def verificar_senha(s, h): return pwd_context.verify(s, h)

# 2. OAuth2 scheme — extrai o token do header Authorization
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/auth/login")

# 3. Criação do token JWT
def criar_token(data: dict) -> str:
    payload = data.copy()
    payload["exp"] = datetime.utcnow() + timedelta(minutes=480)
    return jwt.encode(payload, SECRET_KEY, algorithm="HS256")

# 4. Extrai o usuário autenticado de cada requisição
def get_current_user(token: str = Depends(oauth2_scheme),
                     db: Session = Depends(get_db)):
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=["HS256"])
        cpf = payload.get("sub")
    except JWTError:
        raise HTTPException(401, "Credenciais inválidas")
    user = db.query(Funcionario).filter(Funcionario.cpf == cpf).first()
    if not user: raise HTTPException(401)
    return user
🔐

bcrypt

Algoritmo lento de propósito. Testa apenas centenas de senhas/segundo contra milhões do MD5. Cada hash tem salt aleatório → a mesma senha gera hashes diferentes.

🎫

JWT — crachá digital

String dividida em header.payload.signature. Carrega CPF (sub), cargo e expiração. Assinado com SECRET_KEY → impossível forjar.

🕵️

get_current_user

Em cada requisição: decodifica o JWT, valida a assinatura, checa expiração, busca o usuário no banco e devolve. Se qualquer passo falha → HTTP 401.

Arquivo · dependencies.py

Autorização por cargo

Depois de saber QUEM é o usuário, precisamos saber SE ele pode fazer aquilo.

def require_adm(user = Depends(get_current_user)):
    if user.cargo != CargoEnum.ADM:
        raise HTTPException(403, "Acesso restrito a ADM")
    return user

def require_vendedor(user = Depends(get_current_user)):
    if user.cargo not in (CargoEnum.VENDEDOR, CargoEnum.ADM):
        raise HTTPException(403, "Acesso restrito a Vendedor")
    return user

def require_oficina(user = Depends(get_current_user)):
    if user.cargo not in (CargoEnum.OFICINA, CargoEnum.ADM):
        raise HTTPException(403, "Acesso restrito à Oficina")
    return user
🔽

Cascata de validação

require_adm
   ↓
get_current_user
   ↓
jwt.decode(token)
   ↓
query(Funcionario)
🎯

Uso nas rotas

@router.post("/funcionarios/")
def criar(...,
    _=Depends(require_adm)):
    ...

O _ significa "só quero a proteção, não o retorno".

🚫

401 vs 403

401 = não autenticado (token inválido/ausente).
403 = autenticado, mas sem permissão para essa rota.

Arquivo · routers/

Os 6 routers

Cada arquivo cuida de uma área da API. Tudo segue o mesmo padrão: prefixo, tags, dependências e response_model.

ArquivoPrefixoResponsabilidadeEndpoints
auth_router.py/authLogin e geração de JWT1
funcionarios.py/funcionariosCRUD de funcionários (só ADM)4
veiculos.py/veiculosCRUD + consulta de estoque5
clientes.py/clientesCRUD de clientes4
transacoes.py/transacoesVendas, devoluções, financeiro5
ordens_servico.py/ordens-servicoAbrir, listar e fechar OS4
🎯

Padrão de um router

router = APIRouter(
    prefix="/veiculos",
    tags=["Veículos"]
)

@router.post("/",
    response_model=VeiculoOut,
    status_code=201)
def criar(...):
    ...
🔒

Proteção consistente

Toda rota sensível tem um Depends(require_xxx). Sem isso, o endpoint fica público.

📘

Tags no Swagger

O tags=["Veículos"] agrupa no /docs. Fica organizado por área em vez de uma lista enorme.

Arquivo · main.py

O ponto de entrada

Registra tudo e sobe o servidor. É o arquivo que o Uvicorn executa.

# 1. Cria as tabelas (lê models.py) se não existirem
Base.metadata.create_all(bind=engine)

# 2. Instancia o app com metadados para o Swagger
app = FastAPI(
    title="MotoPrime API",
    version="1.0.0",
    description="Sistema de gestão para concessionária"
)

# 3. Serve arquivos estáticos (/static/css/app.css, etc.)
app.mount("/static", StaticFiles(directory="app/static"))

# 4. Registra os 6 routers (todos os endpoints da API)
app.include_router(auth_router.router)
app.include_router(funcionarios.router)
app.include_router(veiculos.router)
app.include_router(clientes.router)
app.include_router(transacoes.router)
app.include_router(ordens_servico.router)

# 5. Rotas de página (HTML estático, não JSON)
@app.get("/", include_in_schema=False)
def root():
    return FileResponse("app/static/index.html")

@app.get("/dashboard", include_in_schema=False)
def dashboard_page():
    return FileResponse("app/static/dashboard.html")

# ... + /funcionarios, /veiculos, /clientes, /transacoes, /ordens
🏁

É o arquivo que o Uvicorn roda

uvicorn app.main:app --reload

O app.main:app significa "no módulo app/main.py, a variável app".

🌐

API vs Páginas

Endpoints da API (via routers) devolvem JSON.
Rotas de página devolvem arquivo HTML. Ambas convivem no mesmo app.

📊

Swagger automático

Como os routers têm tags e schemas, o FastAPI gera /docs e /redoc sem esforço.
